# 整车功率预算与电池保护管线（Go）

一套可在本地运行、以模拟传感器读数驱动的整车功率预算与电池保护管线。
管线对模拟采样做**有效性判定与状态估计**，依据电池/热状态推导**单调、可解释的功率与转矩上限**，
并在多个驱动/用电单元**并发申请**时按优先级分配功率预算，全程保证结论确定、预算守恒、故障可恢复。

- 语言：Go（module `github.com/lisama569/battery-power-control-go`，Go 1.25+）
- 无第三方依赖，仅使用标准库

## 目录结构

```
internal/sensor/    采样校验（量程/时间戳/跳变/序号）+ 状态估计（融合 + 库仑积分 SOC）
internal/limits/    分段线性降额：温度/SOC/电压 → 功率/转矩上限；故障切断与迟滞
internal/budget/    并发安全的功率预算管理器：优先级分配、降级/拒绝、预留守恒；
                    短时功率增援（boost.go）：窗口内临时提优先级、挤占与到期归还
internal/pipeline/  串联四层，Evaluate 全流程原子一致；管线时钟驱动增援到期
cmd/demo/           本地模拟驱动：坏样本、标称、低温、过温故障与恢复、短时增援六个场景
```

## 数据流

```
模拟采样 ──Validator──拒绝?──► 记录可区分原因（不参与任何计算）
               │接受
               ▼
           Estimator ──► StateEstimate{V,I,T,rpm,SOC,Valid,Notes}
               │
               ▼
         Limits Engine ──► Decision{功率/转矩上限, 各约束, 生效约束, 故障}
               │（上限即本轮总预算）
               ▼
         Budget Manager ──► Allocation{各单元授予, Reserved, Remaining}
```

## 一、状态估计与有效性判定

### 样本判定（`internal/sensor/validator.go`）

判定顺序固定，保证同一输入永远得到同一结论：

1. `bad_channel`：通道未注册；
2. `future`：采样时间戳领先当前时钟超过 50ms；
3. `stale`：样本年龄超过该通道的新鲜度时限；
4. `out_of_range`：NaN/Inf，或超出 `[Min, Max]` 量程（端点本身合法）；
5. 序号倒退：同通道 `Seq` 不大于上一被接受样本（乱序/重放，归入 `jump`）；
6. `jump`：与上一被接受值之差超过 `MaxStep`（读数跳变）。

任何被拒绝样本都**不会更新内部状态、不进入估计器**，并在 `Verdict.Detail` 中给出人类可读原因。
默认通道参数（可在 `Config.Specs` 覆盖）：

| 通道        | 量程          | 最大相邻跳变 | 陈旧时限 |
|-----------|--------------|------------|---------|
| voltage V | [240, 430]   | 30         | 250ms   |
| current A | [-400, 400]  | 350        | 250ms   |
| temp °C   | [-40, 105]   | 15         | 2s      |
| rpm       | [0, 20000]   | 8000       | 250ms   |

`Freshness(now)` 额外检测“从未到样”（`missing`）与“最近到样已陈旧”（`stale`），
使**缺失**与**陈旧**两类故障可区分。

### 状态估计（`internal/sensor/estimator.go`）

- 每路通道只保留最近一次**被接受**的值与时间戳；
- SOC 由电流做梯形库仑积分：`SOC -= mean(I)·dt / 3600 / 容量Ah`，钳位在 [0,1]（正电流为放电）；
- `Estimate(now)` 要求四路必需通道全部到样且未陈旧，否则 `Valid=false` 且 `Notes` 逐通道列出
  `channel:missing` / `channel:stale`。**无效估计不得用于功率决策。**

## 二、限功率与降额规则（`internal/limits/limits.go`）

每条约束把一个物理量经分段线性折线映射为额定功率/转矩的允许比例 `factor∈[0,1]`，再乘以额定值：

- **温度折线**：-20°C→0.55，0°C→0.85，20~45°C→1.00，60°C→0.70，75°C→0.30，85°C→0.05；
- **SOC 折线**：5%→0.05，10%→0.25，20%→0.55，30%→0.80，≥50%→1.00；
- **电压折线**：270V→0.05，300V→0.30，320V→0.60，350V→0.90，≥370V→1.00。

单调性：温度升高、SOC 降低、电压降低时，允许比例只降不升（有单调性测试）。
最终结论取全部约束的**最小值**；约束按 `factor` 升序、同值按名称升序排列，
首个即生效（binding）约束，因此**同一工况重复评估结果逐字段一致、无抖动**。
每个约束自带 `Reason` 文本（如 `temp=-20.0C -> factor 0.55`），结论可解释。

### 故障切断与迟滞

| 故障           | 置位阈值            | 清除阈值（迟滞）        |
|----------------|--------------------|------------------------|
| over_temperature | T ≥ 90°C          | T < 80°C               |
| under_voltage    | V ≤ 260V          | V > 300V               |

置位后输出功率/转矩强制为 0，并增加 `*_cutoff` 约束说明；
在阈值附近回摆不会反复跳变（有迟滞防抖测试）。
输入估计无效时进入安全零输出态，且**不改动**锁存的故障标志，避免坏数据污染故障状态。

## 三、功率预算分配与故障处理协议（`internal/budget/budget.go`）

- 每个单元声明：`Priority`（小者优先）、`RequestW`（期望）、`MinW`（降级下限）；
- 一轮 `Allocate` 原子完成：按优先级（同优先级按 ID 升序，结果可复现）依次授予：
  - 可用预算 ≥ 请求：`granted` 足额；
  - `MinW` ≤ 可用 < 请求：`degraded` 降级授予全部可用量；
  - 可用 < `MinW`：`rejected`，不写入预留；
- `Request` 是对单个单元预留的**原子调整**：把其旧预留纳入可支配额度后重算，
  申请被拒时原样保留旧预留；单元在任意时刻最多持有一笔预留；
- `Release` 幂等，重复释放返回 0、不重复扣减。

守恒不变量（任何方法返回后都成立，并有测试逐轮校验）：

```
ReservedW == Σ 各持有单元 PowerW
ReservedW + RemainingW == TotalBudgetW
ReservedW ≤ TotalBudgetW（剩余额度永不为负）
```

**预算收紧主动回收**：限功率结论变化时，管线原子地把总预算 `SetBudget` 为新的功率上限。
预算下调会**立即**按“优先级从低到高（同优先级按 ID 逆序）”回收已持有预留，
直到恢复守恒：边界单元只回收差额（若差额会击穿其 `MinW` 则整笔收回），
更低优先级单元整笔收回。故障把预算打到 0 时全部预留被收清、**不留残留占用**，
任何新申请都被拒绝；恢复后额度干净可用，单元重新申请即可，不漏计、不重计。
被回收的单元会收到降级原因（如 `budget tightened to 105000.0W: reclaimed 45000.0W by priority`）。

### 短时功率增援（boost，`internal/budget/boost.go`）

超车、避障等短时峰值场景：单元通过 `RequestBoost(BoostSpec{Unit, Priority, TTL})`
发起一段**有时限**的增援，窗口内以临时优先级占用预算：

- **抢占**：可用额度不足时，从生效优先级**严格更低**的持有单元挤占，
  顺序为优先级从低到高、同优先级按 ID 逆序（可复现）；只挤占本次授予所需的额度，
  被挤占单元记录其原始申请。可挤占总量仍达不到 `MinW` 时增援被拒绝，
  且不改写任何既有预留；优先级不低于增援优先级的单元**永远不会被挤占**；
- **到期归还**：窗口一过（由管理器时钟驱动，管线注入评估时间，测试注入固定时钟），
  增援预留移除，被挤占单元按（优先级升序、ID 升序）以**原始申请**在当前可用额度内
  重新授予——预算未变时完全回到增援前状态，如同增援从未发生；
  若预算已收紧，归还按当前可用额度足额/降级/拒绝，守恒始终成立；
- **中途收紧**：增援窗口内限功率上限继续下压时，增援预留与其他预留一起按
  “优先级从低到高”统一回收（增援的临时优先级通常使其最后被触及）；
  故障归零时增援预留一并收清，不卡死、不留残留，恢复后额度干净可用；
- **提前结束**：对增援单元 `Release` 或其发起普通 `Request` 视为提前结束增援，
  立即归还被挤占额度；同一单元重复 `RequestBoost` 先取消旧增援再按新申请处理；
- **与常规轮询的关系**：`Allocate` 跳过持有生效增援的单元（其预留由增援管理），
  其余单元照常按本轮申请分配。

适用边界：增援 TTL 必须为正；增援只重排预算分配，不突破当前限功率结论给出的总量；
归还的是“原始申请在当前预算内的重算结果”，不保证历史功率数值原样恢复
（例如窗口内预算被收紧时，归还结果可能降级）。

## 四、管线一致性（`internal/pipeline/pipeline.go`）

`Pipeline` 用单把锁串行化 `Ingest / Evaluate / Request / RequestBoost / Release / Recover / Reset`。
`Evaluate` 在同一临界区内完成“新鲜度检查 → 状态估计 → 限功率结论 → 更新总预算 → 本轮分配”，
因此外部任何时刻看到的**功率上限、总预算、分配快照三者一致**。报告 `Report` 携带：
状态估计、限功率结论（含全部约束与生效原因）、分配快照（含活跃增援列表）、被拒绝样本与各通道新鲜度。
管线把调用方提供的时间注入预算管理器作为时钟，增援到期由该时钟驱动，
因此同一串输入（样本 + 时间戳）重复运行，结果与日志完全一致。

## 五、本地验证

```bash
# 构建
go build ./...

# 跑模拟演示：坏样本拒绝 / 标称分配 / 低温降额 / 过温切断 / 迟滞恢复 / 短时增援全生命周期
go run ./cmd/demo

# 全量单测（含竞态检测；测试日志打印输入工况与判定依据）
go test ./... -race -count=1 -v

# 仅竞态 + 复现性快速检查（重复 50 次）
go test ./... -race -count=50
```

测试覆盖：

- **sensor**：五类拒绝原因、量程端点、缺失/陈旧区分、库仑积分数值、无效估计、并发安全与可复现；
- **limits**：标称/低温可解释性、三条曲线单调性、同工况重复一致、过温迟滞防抖、无效输入安全态；
- **budget**：优先级分配、降级与拒绝边界、调整/释放幂等、收紧主动回收与故障↔恢复不重不漏、
  16 路并发竞态；增援：抢占与到期归还、窗口内收紧按优先级回收、故障归零无残留与恢复后干净可用、
  可挤占不足时的拒绝不改写既有预留、高优先级单元不可被挤占、并发增援竞态、同输入重放逐字段一致；
- **pipeline**：坏样本端到端拒绝链路、标称分配守恒、过温故障链与迟滞恢复、12 路并发 `Evaluate` 一致性；
  增援端到端生命周期（抢占 → 中途收紧回收 → 故障归零 → 恢复 → 到期归还后与增援前完全一致）、
  8 路并发混合增援/申请/释放/评估。

所有测试用固定时间戳与固定输入，结果可复现；失败信息包含输入工况与具体判定原因。
